## 定位

**它不是"帮你点提交"的机器人，是把 90% 的机械填报做掉的工具。**

报销真正的风险不在"填得慢"，在**填错**：票号抄错、金额不闭合、住宿标准套错、补助和实报重复领、附件漏传。这个 skill 的设计取向是**先把错拦住，再谈自动化**：

- **数据本地**：解析、校验、填报全在本机跑；只有发票文本会进 AI 上下文（所以涉密材料不能用）。
- **不代提交**：可以点【提交线上审批】，但【确认提交审批】永远由本人点 —— 那一步等于通知审批人。
- **不猜数据**：解析不出来就报错退出，不编票号、不编金额、不替你选经费项目。

> [!IMPORTANT]
> 这是 workflow（skill），不是独立软件。宿主是 DeepSeek Harness，模型负责判断，脚本负责动手。
> 学校系统一改版，选择器和流程就可能失效 —— 已知坑那一节就是踩出来的地图，照着改比重写快。

## 安装

1. 解压到 DSH 工作区的 skills 目录：

   ```
   ...\deepseek-harness\default-workspace\skills\ywtb-reimburse
   ```

   （或放到 `~\.dsh\skills\`）

2. 重启 DeepSeek Harness，输入框敲 `/` 能看到 `ywtb-reimburse`。

3. 自检：

   ```powershell
   powershell -File scripts\launch.ps1 -CheckOnly
   ```

   看到 `RESULT: OK` 即可（检查 Node / 内置 Python / Chrome / CDP 9222）。

## 快速开始

```text
① 把发票 zip 丢给 AI，说「帮我报销」
② 确认页填一次：经费项目 / 出差事由 / 职称 / 住宿 / 审核人  → 点【确认，继续填单】
③ 等 6–8 分钟，它跑到审批单
④ 核对金额、附件、担保人 → 你自己点【确认提交审批】
```

第一次用会先弹**设置页**（`127.0.0.1:8799`）填工号 + 密码；密码用 Windows DPAPI 加密存本机，绑定当前账户。

## 它能做什么

| 环节 | 做什么 | 校验 |
|---|---|---|
| 收票 | PDF → 文本（`extract_invoices.py`） | 读不到就报错，不跳过 |
| 解析 | 票号、金额、税额、日期、行程、起终点 | 购买方税号、金额三元组、票号重复、行程与发票金额配对 |
| 确认页 | 把"必须人来定"的字段集中到一个本地网页 | 经费项目只列有余额的；2 开头项目强制不包干 |
| 填单 | 建单 → 主信息 → 住宿明细 → 挂票 → 行程单 → 支付方式 | 每个关键节点回读核对，不一致就覆盖，仍不一致就停 |
| 审批 | 提交线上审批 → 审批单加担保人 → 传非发票附件 | 附件按文件名去重、传后核对条数 |
| 交付 | 停在【确认提交审批】前 | 永不代点 |

**流水线**

```mermaid
flowchart LR
  A[发票 zip] --> B[extract_invoices.py<br/>PDF→文本]
  B --> C[invoice_parse.py<br/>解析+自检]
  C -->|0 错误| D[confirm_server.mjs<br/>确认页 8787]
  D -->|你点确认| E[fill_travel.mjs<br/>建单→住宿→挂票→行程单→支付]
  E --> F[提交线上审批<br/>审批单+担保人]
  F --> G[upload_attachments.mjs<br/>发票以外的附件]
  G --> H([你点确认提交审批])
```

覆盖两条业务线：**国内差旅报销**、**电子发票无纸化报销**。混合单据按 skill 的规则拆单，先问你。

## 填报规则

这些不是"最佳实践"，是**系统真实规则**，代码按这个写：

| 项 | 规则 |
|---|---|
| 飞机行 | 只挂机票 |
| 汽车行 | 只挂汽车票（网约车 / 出租车 / 大巴都算「汽车」，**不看票种**） |
| 汽车费按天 | ≤ 80 元/天 → 不交票，在「市内交通补助」填**天数**；> 80 元/天 → 交票挂**汽车行**，当天不再领补助 |
| 住宿 | 包干时**金额不用填**，系统按「城市 × 淡季天数」自动算；「包干/不包干」变灰不可选 = 住宿明细生效 |
| 出差地点 | **不用填**，住宿明细保存后系统自动带出 |
| 职称职别 | 住宿明细会把它改写成「08其余人员」，脚本回读后自动改回并按确认页核对 |
| 住宿明细顺序 | 工号 → 绿色+ → 检索（省简称如 JS）→ 勾城市 → 填住宿地点 → 保存 → 淡季天数 |

## 架构

```
scripts/
  run.mjs                 唯一入口（配置→解析→草稿→项目→确认页→填单）
  setup.mjs / cred.ps1    首次设置页（工号 + DPAPI 密码）
  extract_invoices.py     PDF → 文本
  invoice_parse.py        文本 → dataset.json（含一致性校验）
  confirm_server.mjs      本地确认页（8787），点确认后自动接力填单
  fill_travel.mjs         差旅单主流程（建单→住宿明细→挂票→行程单→支付→审批单）
  upload_attachments.mjs  审批单附件上传（幂等、去重、传后核对）
  list_projects.mjs       抓可用经费项目（过滤余额 0 / 过期）
  portal.mjs              CAS 登录 + 进报账系统
  cdp.mjs                 零依赖 CDP 驱动（Node 22 自带 WebSocket）
  rules.mjs               市内交通补助规则（80 元/天）
  set_approvers.mjs       审批人（担保人）管理
runtime/                  内置 Python + pypdf
SKILL.md                  给 AI 看的操作手册（含踩坑表）
```

设计约束：**脚本不写死任何个人数据**（工号、项目号、审核人都来自确认页或系统页面）；**浏览器独立 profile**（`%LOCALAPPDATA%\ywtb-skill\profile`），不碰日常 Chrome。

## 已知坑

系统页面是 ASP.NET WebForms，回发、弹窗、layui 上传都会咬人。下面每一条都是实测踩出来的，代码里已经处理：

<details>
<summary><b>1. 合成 click 不触发回发</b></summary>

`下一步（支付方式）`、`编辑流程`、`开始上传` 用 `element.click()` 没反应：有的不提交表单，有的走 `noFile()` 把上传队列清空。
**必须用 CDP 发真鼠标事件**（`Input.dispatchMouseEvent`），且坐标要加主框架 60px 偏移。
</details>

<details>
<summary><b>2. 勾选「出差地区」会 <code>__doPostBack</code></b></summary>

住宿地点输入框（`TB_ZSDDQR`）是回发之后才渲染的。在同一个 eval 里"勾选 + 填字"必然写空 —— 要分两步：真点勾 → 等回发 → 再填。
</details>

<details>
<summary><b>3. 保存后可能退回列表</b></summary>

校验不过时系统退回「未提交单据」，页面值看着对但没入库。要回读列表金额，对不上就停，别继续点。
</details>

<details>
<summary><b>4. 票夹会捡到旧票（6 张显示 8 张）</b></summary>

删掉的草稿会把发票释放回票夹。上传前必须先读票夹已有票号，**只补传缺的那几张**，否则 2 张旧票 + 6 张新票 = 8。
</details>

<details>
<summary><b>5. 明细页底部「合计」是前端汇总</b></summary>

挂完汽车票后那个格子经常不重算（显示 1730，实际 2403）。**以列表金额 / 支付页「单据报销金额」/ 审批单合计为准**，别拿它当校验依据。
</details>

<details>
<summary><b>6. 附件表里混着发票</b></summary>

「上传附件列表」同时列着系统自动绑定的发票。只有带删除链接（`LINK_DEL`）的行才是真附件；上传后要刷新页面再核对条数。
</details>

<details>
<summary><b>7. 一张发票只能绑一张单</b></summary>

票夹可用为 0 时，先查是不是被别的草稿占用了，删掉那张草稿再跑。
</details>

## FAQ

**Q：提示要重新登录？**
会话 7–14 天过期。让 AI 重新登录，或自己在弹出的 Chrome 里登一次（勾「7 天免登录」）。

**Q：浏览器起不来 / 9222 端口占不上？**
先关掉所有 Chrome 再跑；脚本用的是独立配置。个别环境需要一次管理员授权。

**Q：提示"职工号错误"？**
报销人框残留了内容。清空后重输工号再回车。

**Q：保存报「请填写出差地点」，但框是灰的？**
系统模板缺陷（字段被写成 `disabled`，本意可填）。脚本会自动解除禁用；现在正常情况下它由住宿明细自动带出。

**Q：填到一半想退出？**
直接关标签页，单据不会保存。已保存的草稿在【未提交单据】里可删除。

**Q：为什么不干脆点提交？**
提交等于进审批流并通知审批人，涉及责任归属。这一步必须本人确认。

## 分发给同事

把 `ywtb-reimburse.zip` 发给对方，解压到 `~\.dsh\skills\` 即可。

**包里不要带**：

| 不要打包 | 原因 |
|---|---|
| `.ywtb.config.json` | 你的工号 |
| `.ywtb.cred` | 你的加密密码（DPAPI） |
| `.browser-profile*/` | 登录 Cookie |
| `invoices/`、`finance_recon/` | 你的发票与截图 |

凭据各人录一次 —— DPAPI 绑定 Windows 账户，别人的加密文件解不开，这是设计如此。

## 安全与边界

- 本地服务只监听 `127.0.0.1`（8787 确认页 / 8799 设置页）。
- 发票内容会进 AI 上下文，**涉密材料不要用**（学校明令「涉密不上网」）。
- 不把身份证、银行卡、手机号写进任何输出文件。
- 最终提交永远由本人完成；解析不出的字段一律标「需人工」，不猜。
- 仓库未附开源许可证；对外发布前请先加 `LICENSE`。
